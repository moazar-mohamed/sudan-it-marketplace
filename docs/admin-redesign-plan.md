# خطة إعادة تصميم لوحة السوبر أدمن (الاتجاه أ)

حالة الخطة: **للمراجعة فقط**. لم يُنفَّذ شيء في الكود. التصميم المرجعي: ملف Design «نظام تصميم لوحة السوبر أدمن» (الصفحات «الاتجاه أ»). أسلوب «مركز العمليات» مستبعَد.

## 0. قواعد ملزمة

1. **لا تضيع أي عملية.** المرجع: لوحة «خريطة العمليات» (٥٣ عملية). تُثبَّت في اختبار آلي (المرحلة ٥).
2. **اللوحة الحالية يستخدمها شخص الآن.** لا نشر على الموقع الحالي دون موافقة صريحة منك. المعاينة على رابط منفصل.
3. **لا تغيير في** قواعد Firestore، ولا البيانات، ولا طبقة `src/data/**`، ولا الروابط (URLs) الحالية.
4. **لا commit ولا push** حتى تقول.
5. لا أرقام إصدارات.

## 2. بيئة العمل الآمنة (المرحلة ٠)

- **شجرة عمل منفصلة (git worktree) وفرع جديد `feat/admin-redesign` من master**، كي لا نلمس تعديلات `customer_web` غير المثبّتة، ولا نخلط العملين.
- **مفتاح تشغيل `data-ui="v2"`** على عنصر `<html>`:
  - الافتراضي: القديم. التصميم الجديد لا يظهر لأحد إلا بتفعيله (`?ui=v2` أو من الإعدادات، ويُحفظ في المتصفح).
  - كل أنماط الجديد داخل `[data-ui='v2']`، فلا تأثير على القديم حتى لو نُشر الكود.
- **المعاينة:** `firebase hosting:channel:deploy redesign --only hosting` (قناة معاينة مؤقتة على Spark، رابط مستقل). لا يمس الموقع الحالي.
- **خط أساس:** نسجل عدد الاختبارات الناجحة قبل البدء (الحد الأدنى للمقارنة)، ونلتقط لقطات للصفحات الحالية عبر المحاكي للمقارنة.

- `src/theme/ui.ts`: مفتاح الشكل الجديد (`data-ui="v2"` عبر `?ui=v2`) والكثافة (`data-density`)، وكلاهما مطفأ افتراضيًا. نص قصير في `index.html` يطبّقهما قبل أول رسم.

- صفحة داخلية مخفية `/design-system` فيها مفاتيح التشغيل والألوان والخط والأزرار والحبوب والرقائق والتبويبات والصفوف وقائمة «⋯» ومجموعات الإجراءات.
- اختبارات جديدة (٢٢): الهوية محفوظة، التباين ٤٫٥ إلى ١، كل متغيرات القديم معرّفة، ولا قاعدة خارج `data-ui='v2'`.
- النتيجة: `tsc` نظيف، `eslint src` نظيف، `vitest` **٨١ ملفًا و٨٢٨ اختبارًا ناجحًا** (كان ٨٠٦)، والبناء ينجح. شاهدتها بالعين فاتحة وداكنة ومضغوطة.

### نتيجة المراحل ٢ إلى ٧ (منفَّذة في الفرع، غير مثبّتة)
- **٢ القشرة:** قائمة جانبية بثمانية أقسام وفروعها، وشريط علوي (بحث + جرس + قائمة المستخدم: ملف، كلمة مرور، لغة، مظهر، كثافة، رجوع للقديم، خروج)، وشريط الجوال بخمس خانات. كل رابط قديم يقع في قسم، وبعضها في قائمة المستخدم.
- **٣ المكوّنات:** إعادة تنسيق الأصناف الحالية (بطاقة، جدول، رقاقة، زر، حقل، نافذة…) بالشكل الجديد، ومكوّنات جديدة: `SectionTabs` (تبويبات القسم تلقائيًا)، `SidePanel`، `SplitView`، `ActionGroup`، `BulkBar`، `FilterGroup`.
- **٣٫٥ التصاميم المكمّلة** في ملف التصميم: الدخول، المحذوفات، الحالات والجرس، الداكن، الجوال.
- **٤ الصفحات:** الطلبات (تفاصيل في لوحة جانبية + الفلاتر في زر واحد) والعملاء (لوحة جانبية، والتحويل والحذف في مجموعة حساسة) والدخول. بقية الصفحات تأخذ الشكل الجديد من القشرة وإعادة التنسيق دون تغيير ترتيبها بعد.
- **٥ ضمان العمليات:** الأمر `npm run test:v2` يشغّل كل اختبارات الصفحات والشكل الجديد مفروض، فيثبت أن عمليات الصفحات الحالية لا تزال موجودة. النتيجة ٨٧٠ ناجحًا و٩ متخطّاة عمدًا (اختبارات «الشكل الافتراضي»).
- **٦ الجودة:** `tsc` و`eslint` نظيفان، والبناء ينجح، والاختبارات العادية ٨٧٩ ناجحًا.
- **٧ المعاينة:** نُشرت على قناة معاينة `redesign` (تنتهي ٢٠٢٦-١١-١٠) بلا مساس بالموقع الحي، ويُفعَّل الشكل الجديد بـ `?ui=v2`.
- **الصفحات العميقة (منفَّذة لاحقًا):** صفوف الشركات بزر سريع وقائمة «⋯»، قائمة «⋯» للمنتجات (عرض، إنهاء العرض، إخفاء بسبب، إظهار)، البلاغات في لوحة جانبية كصندوق وارد، طلبات الخدمة في لوحة جانبية، تبويبات التحليلات (مبيعات، شركات ومنتجات، إلغاءات، استخدام)، الإعدادات على الإشعارات فقط (اللغة والمظهر في قائمة المستخدم)، وبطاقات التصنيفات بالشكل الجديد.
- **لم يُنفَّذ بعد:** اختبارات القواعد (المحاكي) قيد التشغيل، ومشاهدة الشاشات على البيانات الحقيقية (تحتاج حساب أدمن)، والتبديل للموقع الحي (يحتاج موافقتك).

## 3. المراحل

كل مرحلة تنتهي باختبارات خضراء (`npm test`, `npm run typecheck`, `npm run lint`) وعرض لك قبل التي بعدها.

### المرحلة ١: السيستم (أساس الشكل)
- طبقة متغيرات جديدة (ألوان الاتجاه أ، زوايا ١٦/٢٠، ظل خفيف، أحجام الخط) تحت `[data-ui='v2']`، مع الوضع الداكن.
- الكثافة: **مريحة هي الافتراضية للكل (قرارك)**. خيار «مضغوط» اختياري من قائمة المستخدم (`data-density`)، ويمكن حذفه إن لم تُرِده.
- **الملفات:** `styles.css` (قسم جديد في نهايته)، `theme/theme.ts` (مفتاح v2 والكثافة).
- **القبول:** صفحة تجريبية داخلية تعرض كل الأزرار والحبوب والحقول بالفاتح والداكن.

### المرحلة ٢: القشرة (الشريط الجانبي والعلوي)
- شريط جانبي بـ٨ عناصر مع فروع للقسم النشط (الكتالوج: منتجات/خدمات/تصنيفات/عروض، إلخ).
- شريط علوي: بحث Ctrl K + جرس التنبيهات + قائمة المستخدم (ملف شخصي، كلمة المرور، لغة، مظهر، كثافة، خروج، حذف حسابي).
- الجوال: شريط تبويبات سفلي من خمس خانات + «المزيد».
- **الروابط القديمة كلها تبقى تعمل** (`/products`, `/services`… تُعرض داخل القسم الصحيح).
- **الملفات:** `Layout.tsx`، `navItems.ts`، `AlertsBell.tsx`، `CommandPalette.tsx`، مكوّن جديد `UserMenu.tsx`.
- **القبول:** اختبارات `Layout.test.tsx` المحدّثة، والتنقل بين كل الأقسام.

### المرحلة ٣: المكوّنات المشتركة
`PageHeader`، `SubTabs` (مربوطة بالمسار)، `FilterChips`، `RowList` (صفوف بطاقات)، `DataTable` (ترويسة ثابتة، أعمدة محاذاة)، `RowMenu` بمجموعات وعنصر «حساس»، `SidePanel` (لوحة جانبية بأقسام)، `DangerZone`، `FiltersPopover`، `BulkBar`.
- القوائم الرقمية (طلبات، منتجات، تحليلات) على `DataTable`، والكيانات (شركات، عملاء) على `RowList`.
- **القبول:** اختبار لكل مكوّن، وإتاحة لوحة المفاتيح وقارئ الشاشة.

### المرحلة ٣٫٥: إكمال التصاميم الناقصة (في ملف التصميم، قبل أي صفحة)
تسجيل الدخول، المحذوفات، الملف الشخصي (كنوافذ)، صفحات التفاصيل بروابط مباشرة، التحميل والفراغ والخطأ، الوضع الداكن، الجوال، لوحة الجرس، إضافة شركة، نماذج التصنيف، قسم «متقدم». **تراجعها وتوافق قبل المرحلة ٤.**

### المرحلة ٤: الصفحات (الأقل خطرًا أولًا)
1. الرئيسية (مهامك اليوم، المبيعات، التصنيفات، آخر الطلبات) + بطاقة الترحيب مصغّرة.
2. الطلبات + طلبات الخدمة كتبويب + لوحة التفاصيل (إيصال، إلغاء بسبب).
3. الشركات + تفاصيل الشركة + نموذج التعديل بأقسام (موقع، نقاط استلام، مدن، سجل).
4. الكتالوج: منتجات، خدمات، تصنيفات (سحب + نقل + رفع/خفض)، عروض.
5. العملاء + التقييمات + لوحة التفاصيل (تحويل/حذف في «منطقة حساسة»).
6. البلاغات (صندوق وارد).
7. التحليلات (تبويبات: مبيعات، شركات ومنتجات، إلغاءات، استخدام).
8. الإعدادات: إشعارات وصيانة (+«متقدم»)، مدن، مشرفون، سجل النشاط.
9. المحذوفات: **صفحة مستقلة** (قرارك)، تبويب في الإعدادات. النقل إليها من «⋯» وقسم «منطقة حساسة»، والاستعادة والحذف النهائي من الصفحة نفسها. + الدخول.
- **القبول لكل صفحة:** اختباراتها الحالية تمر بعد تحديثها، وتعمل بالعربي والإنجليزي والفاتح والداكن والجوال.

### المرحلة ٥: ضمان عدم ضياع العمليات
- اختبار `operations-coverage.test.tsx`: قائمة الـ٥٣ عملية، وكل واحدة تُفتح فعليًا في واجهة v2 (زر أو عنصر قائمة أو حقل) وتصل إلى نفس الدالة في `src/data`.
- مقارنة آلية بين أسماء العمليات في الواجهة القديمة والجديدة (مفاتيح الترجمة المستعملة).

### المرحلة ٦: الجودة
- تباين الألوان ٤٫٥ إلى ١، أسهم مع الألوان في الأرقام الاتجاهية، تركيز لوحة المفاتيح.
- أداء: الصفحات تبقى `React.lazy`، ولا قراءات إضافية على Firestore (Spark: حدّ ٥٠ ألف قراءة يوميًا).
- RTL/LTR، والوضع الداكن، وحالات التحميل والفراغ والخطأ.

### المرحلة ٧: المعاينة والتبديل
1. نشر قناة المعاينة (بعد موافقتك) وتجربتك أنت وصاحب الاستخدام.
2. قائمة قبول (checklist) بالعمليات الـ٥٣ تُؤشَّر يدويًا في المعاينة.
3. تبديل الافتراضي إلى v2 **بقرارك**، مع إبقاء القديم خلف المفتاح لإصدار واحد كرجوع سريع.
4. بعد استقرار ذلك: حذف القديم.
