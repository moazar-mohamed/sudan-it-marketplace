# خطة بناء موقع العملاء (customer_web)

الموقع نسخة ويب لواجهة العميل في التطبيق. مبني بـ React وVite وTypeScript، ويقرأ نفس بيانات Firebase بنفس قواعد Firestore الحالية.

القواعد الثابتة:

- المنطق يُنقل من التطبيق كما هو (البحث، الترتيب، الفلاتر، الأسعار)، والتطبيق هو المرجع عند أي اختلاف.
- لا تعديل على قواعد Firestore بدون موافقة.
- لا commit ولا نشر إلا بأمر صريح.

## المراحل

| المرحلة | المحتوى | الحالة |
|---|---|---|
| 0: الأساس | تسجيل الدخول، الرئيسية Bento، بحث Ctrl+K، مظهر فاتح/داكن | تمت |
| 1: الحساب والدخول | إنشاء حساب، نسيت كلمة المرور، جوجل، اختيار المدينة، صفحة الحساب، الإعدادات، الإشعارات، البلاغات، الحسابات المحذوفة/المحوّلة | تمت |
| 2: التصفح | القسم، التصفح الكامل، البحث، المنتج، الشركة، الخدمة، التقييمات (قراءة) | تمت |
| 3: الشراء والطلبات | الشراء مع خريطة التوصيل، الدفع اليدوي والإيصال، بانتظار التحقق، الطلبات، التفاصيل، التقييم (الإلغاء من الشركة فقط كما في التطبيق) | تمت، وتحتاج نشر إصلاح قاعدة الطلب أدناه |
| 4: المحادثات والخدمات | المحادثات، زر «تواصل»، طلب خدمة | لم تبدأ |
| 5: الصقل | نسخة الموبايل، شاشة الصيانة وإشعارات المنصة، الحالات الفارغة والأخطاء، لوحة المفاتيح، اختبارات، بناء الإنتاج | لم تبدأ |
| 6: النشر | موقع Hosting ثاني، إضافة عنوانه لنطاقات تسجيل الدخول المصرّح بها، تجربة الدخول بجوجل، ثم مراجعة موضوع SEO | لم تبدأ |

## قرارات معلّقة

1. اللغة: الموقع عربي فقط الآن، ويُضاف الإنجليزي لاحقًا عند الحاجة.
2. خريطة اختيار موقع التوصيل: مضافة بـ Leaflet وخرائط OpenStreetMap.
3. قاعدة إنشاء الطلب كانت تتجاوز حد 1000 عملية في Firestore، فكان طلب التوصيل الثاني يُرفض. أُصلحت في `firestore.rules` مع اختبار `order-expression-limit`، ولم تُنشر بعد.

## ملاحظات للمرحلة 5

- حجم الحزمة الرئيسية حوالي 980 KB، ويحتاج تقسيمًا حسب الصفحات.

## خارج النطاق

- الإشعارات الفورية (push) على الويب.
- المفضلة والمقارنة، لأنهما غير موجودتين في التطبيق.
