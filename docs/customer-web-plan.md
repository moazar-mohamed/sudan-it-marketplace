# خطة بناء موقع العملاء (customer_web)

الموقع نسخة ويب لواجهة العميل في التطبيق. مبني بـ React وVite وTypeScript، ويقرأ نفس بيانات Firebase بنفس قواعد Firestore الحالية.

القواعد الثابتة:

- المنطق يُنقل من التطبيق كما هو (البحث، الترتيب، الفلاتر، الأسعار)، والتطبيق هو المرجع عند أي اختلاف.
- لا تعديل على قواعد Firestore بدون موافقة.
- لا commit ولا نشر إلا بأمر صريح.

## المراحل

| المرحلة | المحتوى | الحالة |
|---|---|---|
| 0: الأساس | تسجيل الدخول، الرئيسية Bento، بحث Ctrl+K، مظهر فاتح/داكن | تمت |
| 1: الحساب والدخول | إنشاء حساب، نسيت كلمة المرور، جوجل، اختيار المدينة، صفحة الحساب، الإعدادات، الإشعارات، البلاغات، الحسابات المحذوفة/المحوّلة | تمت |
| 2: التصفح | القسم، التصفح الكامل، البحث، المنتج، الشركة، الخدمة، التقييمات (قراءة) | تمت |
| 3: الشراء والطلبات | الشراء مع خريطة التوصيل، الدفع اليدوي والإيصال، بانتظار التحقق، الطلبات، التفاصيل، التقييم (الإلغاء من الشركة فقط كما في التطبيق) | تمت |
| 4: المحادثات والخدمات | المحادثات (تحميل الأقدم تلقائيًا، بحث، غير المقروءة، علامة القراءة، بطاقة السياق، القائمة والمحادثة جنبًا إلى جنب)، زر «تواصل»، طلب خدمة بمسودة، طلبات الخدمة وتفاصيلها وتقييمها | تمت |
| 5: الصقل | تقسيم الملفات، حفظ البيانات في المتصفح مع مسحها عند الخروج، تحديث تلقائي للإصدار الجديد، شاشة الصيانة وتنبيهها المسبق، إعلانات المنصة، شريط انقطاع الإنترنت، إعادة المحاولة بدون تحديث الصفحة، مراجعة الموبايل | تمت |
| 6: النشر | موقع Hosting ثاني، إضافة عنوانه لنطاقات تسجيل الدخول المصرّح بها، تجربة الدخول بجوجل (تمت)، ثم مراجعة موضوع SEO | جزئيًا |

المفضلة أُضيفت للمنتجات والخدمات في التطبيق والموقع، وتُحفظ في حساب العميل.

## قرارات معلّقة

1. اللغة: عربي وإنجليزي من الإعدادات وصفحات الدخول، بنفس طريقة التطبيق، والعربي هو الافتراضي.
2. خريطة اختيار موقع التوصيل: مضافة بـ Leaflet وخرائط OpenStreetMap.
3. قاعدة إنشاء الطلب كانت تتجاوز حد 1000 عملية في Firestore، فكان طلب التوصيل الثاني يُرفض. أُصلحت في `firestore.rules` مع اختبار `order-expression-limit`، ونُشرت.

## ملاحظات للمرحلة 5

- قُسّمت الحزمة حسب الصفحات. أكبر جزء الآن مكتبة Firebase (حوالي 180 KB مضغوطة)، ولا يمكن تقسيمها أكثر.

## خارج النطاق

- الإشعارات الفورية (push) على الويب.
- المقارنة، لأنها غير موجودة في التطبيق.

## الصفحات العامة لمحركات البحث (SEO) — 2026-11-05
الموقع كله خلف تسجيل الدخول وقواعد Firestore تمنع القراءة لغير المسجّلين، فقوقل وواتساب لا يريان إلا صفحة الدخول. وافق المالك أن يكون الكتالوج عامًا (الأسماء والأسعار والصور)، فبُني مولّد صفحات ثابتة مجاني على خطة Spark، **دون تغيير القواعد**.

**ما يُنشأ** (تحت `/catalog/`، خارج التطبيق فلا يتعارض معه): الرئيسية، صفحة لكل تصنيف فيه منتجات، وصفحة لكل منتج وشركة، مع `sitemap.xml` و`robots.txt` ووسوم المعاينة (Open Graph) وبيانات Product وBreadcrumb. زر الصفحة يفتح مسار التطبيق (`/product/<id>`) لتسجيل الدخول والشراء.

**ما يظهر:** المنتجات المنشورة غير المخفية ومخزونها أكبر من صفر وشركتها فعّالة وتصنيفها فعّال (كما يراها العميل). للشركة: الاسم والشعار والنبذة فقط. **لا هاتف ولا بريد ولا عنوان ولا موقع ولا حسابات دفع** (لا تُجلب أصلًا من Firestore).

**التحديث:** الصفحات لقطة من وقت التشغيل؛ تتحدث عند إعادة التشغيل فقط (التحديث التلقائي يحتاج Cloud Functions على Blaze):
```bash
npm --prefix customer_web run seo        # يقرأ البيانات الحية بدخول Firebase CLI (firebase login مرة واحدة)
npm --prefix customer_web run build      # ابنِ بلا ملف .env.local الذي فيه VITE_EMULATOR=1
firebase deploy --config firebase.customer.json --only hosting
```
خيارات `seo`: `--emulator` (المحاكي المحلي)، `--fixture ملف.json`، `--site-url https://نطاقك` (عنوان الصفحات؛ غيّره حين يُشترى دومين وأعد التوليد). بديلًا عن دخول الـCLI: `SEO_ACCESS_TOKEN` أو `GOOGLE_APPLICATION_CREDENTIALS` (ملف حساب خدمة).

الملفات: `customer_web/scripts/seo/site.mjs` (العرض، مُختبَر)، `generate.mjs` (القراءة والكتابة). المُولَّد (`public/catalog/` و`public/sitemap.xml`) خارج git.
